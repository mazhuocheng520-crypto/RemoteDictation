# 原理与排查记录

本文记录 RemoteDictation 的几个关键设计是怎么定下来的。数据来自真实环境：Windows 11 本机、ToDesk 5.2、豆包输入法、远端 macOS。工具源码在 [tools/InputProbe.cs](../tools/InputProbe.cs)，只记录按键次数、键码、窗口类名和字数，不记录任何正文。

## 1. 远控软件在前台时吞键

**现象**：远控画面在前台时，按 F9，监听程序一个事件都收不到；换成本机其他窗口在前台时，同样的按键能收到。

**实验**（`InputProbe watch`）：同时挂两个低级键盘钩子。一个在程序启动时安装，另一个在 ToDesk 每次到前台后重新安装。5 分钟内用户在 ToDesk 里按了 37 次 F9：

| 钩子 | 收到 F9 | 收到其他键 |
| --- | --- | --- |
| 启动时安装 | 0 | 64 |
| ToDesk 到前台后重装 | 37 | 296 |

**结论**：低级键盘钩子按“后装先调用”的顺序执行。ToDesk 获得前台时会安装自己的钩子，拦下物理按键不往下传。比它先装的钩子（包括输入法自己的）都看不到。

**做法**：远控窗口到前台约 300 ms 后重装本程序的钩子，之后每 3 秒补装一次（按住语音键期间不重装），保证排在远控软件前面。

## 2. 输入法不接受模拟按键

**实验**（`InputProbe altseq`）：让本工具自己的输入框获得焦点，用 SendInput 模拟按住左 Alt 5 秒，共试三种方式：仅虚拟键码；虚拟键码 + 扫描码 + 自动重复；仅扫描码 + 自动重复。三种都是 0 字，豆包的语音窗口也一次没出现。

**结论**：豆包只响应真实按键，不能靠程序“替你按”语音键。

## 3. 按住 Alt 只有一次“按下”

**现象**：程序在检测到 Alt 后把前台切到本机浮窗，但要再按一次 Alt 豆包才开始听写。

**诊断日志**显示：切换后再没有任何 Alt 按下事件到达，直到用户第二次按下。也就是说，按住修饰键不会产生自动重复，整个按住过程只有一次“按下”。如果这次按下已经被远控软件拿走，输入法就再也等不到了。

## 4. 在按下送达之前切前台

**实验**（`InputProbe preswitch`）：在钩子回调里，也就是这次 Alt 按下还没被系统派发的时候，同步把前台切到本工具的输入框（耗时约 20 ms），然后放行这次按下。用户只按一次、按住说话：9 次中 8 次直接出字。

**做法**：正式程序的钩子跑在独立线程上。检测到远控前台的语音键按下时，同步请求界面线程显示并激活听写浮窗（最多等 300 ms，超时就放弃），再放行按键。之后的情况分别处理：

- 很快松开（只是点一下）：浮窗立即撤回，前台还给远控。
- 按住期间按了其他键：判定为 Alt 组合键，先切回远控，再按顺序补发“Alt 按下 + 这个键”。远控软件接受补发的按键，所以远端照常收到 Option 组合。
- 按住期间点鼠标：输入法还没开始的话，安静撤回。

## 5. 等输入法整理完再粘贴

豆包在松开后还会“整理”文字（标点、口语修正）。固定等几秒容易把半成品收走。现在的完成条件是：组字（IME composition）已经结束，文字至少 1.5 秒没有变化，并且距松开至少 0.8 秒；最长等 20 秒。如果从头到尾没有出现组字和文字，说明输入法没开始，安静撤回。

粘贴时先备份本机剪贴板，写入文字后记下剪贴板序号。然后激活原远控窗口（同一个 HWND、进程号和进程启动时间），等远控软件同步剪贴板（默认 0.8 秒）。期间如果窗口变了、剪贴板被别人改了，就取消，文字留在浮窗。最后只发 Ctrl+V（或 Win+V），从不发回车。

## 6. 权限

远控软件常以管理员（High 完整性）运行。Windows 的 UIPI 机制下，普通权限进程既收不到它前台时的按键，也不能向它发送输入。因此本程序需要以管理员权限运行。开机自启使用“任务计划程序 · 登录时 · 最高权限”，不会弹 UAC 提示。

## 7. 不同远控软件的粘贴键不一样

实测 ToDesk 默认把 Windows 的 Ctrl 映射成 Mac 的 Command，UU 远程默认把 Win 映射成 Command。程序一律发 Ctrl+V 时，UU 那边收到的是 Control+V，什么也不会发生。

远控软件不会告诉本机“远端有没有贴上”，本机唯一能看到的是远控画面。所以每次粘贴前后各截一次远控窗口（缩小成灰度图，只在内存里比较），画面有明显变化就算贴上了：

- 还不知道某个软件用哪个键时，先试 Ctrl+V，没变化再试 Win+V，生效的那个记住，以后直接用；
- UU 远程的映射可以从它自己的设置文件读出来，直接使用；
- 已知的键发出后画面仍没变化，就弹出不抢焦点的提醒，文字保留，可以再贴或换键再贴。

另一个坑：粘贴前如果先隐藏本机浮窗，系统可能把前台交给任务栏，之后再切回 UU、向日葵会被前台锁拒绝。所以要趁浮窗还在前台时先切回远控窗口，再隐藏浮窗。
